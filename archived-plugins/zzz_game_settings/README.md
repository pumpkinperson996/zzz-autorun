# 游戏设置调整插件（zzz_game_settings）

一条龙运行时自动把《绝区零》游戏设置写成「低画质 + 一条龙运行要求」，结束后
还原为用户原始设置。设置直接写入游戏本地文件 `GENERAL_DATA.bin`，无需游戏内 UI 导航。

## 工作方式与代价（请先读）

游戏只在**启动时**读取设置文件，改磁盘不影响运行中的游戏。因此「游戏设置调整」和
「游戏设置还原」都采用「关闭游戏 → 写设置 → 重新打开游戏进大世界」的流程：

- **游戏设置调整**（列表最前）：关游戏 → 写低画质 → 重开游戏（此时游戏以低画质加载）。
- **游戏设置还原**（列表最后）：关游戏 → 写回用户设置 → 重开游戏（游戏以用户设置加载，
  一条龙最终关闭游戏时退出回写的仍是用户设置）。

**代价**：这两步各会触发一次完整的游戏重启+登录（约 1–2 分钟），即每次一条龙比平时
多约两次登录。对无人值守/挂机场景通常可接受；若你更在意速度，可暂不启用本插件。

## 安装

把整个 `zzz_game_settings/` 目录放进项目根的 `plugins/` 下，重启一条龙（或刷新应用注册）。
插件会注册两个应用到一条龙运行列表：

- **游戏设置调整**（`game_settings_apply`）
- **游戏设置还原**（`game_settings_restore`）

## 排序要求（重要）

在一条龙运行界面把两个应用这样排序：

- **「游戏设置调整」排在最前**——它在游戏启动前快照并写入目标设置。
- **「游戏设置还原」排在最后**——它在所有任务结束、关闭游戏后还原用户设置。

排错顺序不会损坏设置，但会削弱效果：调整排在中间会多重启一次游戏；还原排在中间会让
后续任务以用户高画质运行。

## 设置项

在「游戏设置调整」的设置里可配置：

- **启用游戏设置调整**：总开关，关闭后不改动任何游戏设置。
- **帧率 60（关闭则 30）**：一条龙运行期间锁定的帧率。
- **应用最低画质**：关闭后仅写入运行要求四项（镜头自动跟随=关、伤害跳字=关、
  字体=全局细体、帧率），画质保持用户原状。

## 会被写入的设置

运行要求项（始终写入）：镜头自动跟随=关闭、战斗伤害跳字=关闭、字体=全局细体、帧率=30/60。

低画质项（开启「应用最低画质」时写入）：垂直同步/运动模糊/扭曲/高光溢出/抗锯齿/角色动态高精度=关闭，
渲染精度=0.8，阴影/特效/角色/场景/着色/全局光照/各向异性/体积雾/镜面反射=最低档。

不改动：显示模式/分辨率（由一条龙启动参数覆盖）、HDR（由现有机制处理）、镜头灵敏度
（一条龙灵敏度校准可适配任意值）。

## 崩溃恢复

用户原始设置的快照持久化在 `config/{实例}/one_dragon/game_settings_apply_state.yml`，并带
`snapshot_pending` 标记：

- 正常流程：调整时快照并置位标记，还原成功后清除标记。
- 若某轮中途崩溃/手动停止导致未还原：下一轮「调整」发现标记仍在，**不会**用当前（已被改低的）
  设置覆盖快照，而是保留原始快照；本轮「还原」成功后用户设置恢复为崩溃前状态。
- 代价：崩溃后、下一轮开始前手动改的游戏设置会被上一轮快照覆盖。

## 游戏版本更新后的表现

`GENERAL_DATA.bin` 格式与设置 ID 是逆向所得，游戏大版本更新可能改变它们：

- **格式/加密变化**：写盘前的往返自检会失败，插件**安全放弃写入**（本轮不调设置，一条龙照常运行），
  日志输出「游戏版本可能已更新」。不会写坏文件。
- **设置 ID 含义变化**：自检无法察觉（格式合法但语义错位），可能写错设置项。若发现设置被改成意外值，
  请更新 `setting_ids.py` 中的 ID 表。还原始终用整块回写，不受 ID 语义影响，用户设置可恢复。

每次写盘前都会把原文件备份为 `GENERAL_DATA.bin.bak_<时间戳>`（保留最近 5 份），可手动回退。

## 测试

```shell
uv run --env-file .env pytest plugins/zzz_game_settings/tests/
```

单元测试离线运行，用合成样例文件覆盖编解码往返、外科手术改值/插入、快照还原、
安全写入备份/复核、崩溃恢复标记持久化，不依赖真实游戏文件。
